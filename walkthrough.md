## 2026-10-07 (Fix CLI forget/purge command tree)

- Findings: `cmd/cli/main.go` declared the top-level `forget` command twice verbatim (a merge artifact), and the `purge` command carried a stray `forget` child — a soft-delete nested under a hard-delete command, which made `stash purge forget` nonsensical. The migration numbering gap (no `00003`) was deliberately left alone — goose does not care and renumbering migrations is riskier than it looks.
- Actions: Edited `cmd/cli/main.go` — removed the duplicate `forget` block, removed the stray `forget` nested under `purge`, and added a `fact` child (`Action: purgeFactCmd`) beside `episode`. ## 2026-10-09 (Guard reasoner output cost: max_tokens + optional JSON mode)

- Findings: LiteLLM usage data showed the `stash` key spending ~$4.62 in total, almost entirely on 2026-10-08 ($4.13): ~10.3M completion tokens versus 1.9M prompt tokens across 3,769 requests — about 2,745 output tokens per call, for responses that should be sub-200-token JSON. Root cause: the configured model was a reasoning-style model and the reasoner sent no `max_tokens`, so nothing capped the output.
- Conclusions: Output tokens, not the architecture, drove the cost. Added a configurable `max_tokens` guard (default 1024; `0` means unlimited, and the field is omitted when 0 so we never request zero output) and an opt-in `response_format=json_object` (default off, because support varies by provider and an unsupported value returns a 400). The eight identical chat call sites were collapsed into one `chat()` helper so request options live in a single place. The real fix remains choosing a non-reasoning instruct model.
- Actions: `internal/reasoner/openai.go` — added `maxTokens`/`jsonMode` fields, a central `chat()` helper, and switched all 8 reasoner methods to it. `internal/config/config.go` — new `STASH_REASONER_MAX_TOKENS` (default 1024) and `STASH_REASONER_JSON_MODE` (default false). `internal/bootstrap/bootstrap.go` — passed both through to the reasoner. `.env.example` — documented both, with a note to prefer a non-reasoning instruct model. Validated with `go build ./...`, `go vet ./...`, `go test ./...` and `gofmt -l .` (all clean).

## 2026-10-09 (Stash weigerde te starten: optionele embedding-overrides waren verplicht)

- Findings: Stash startte niet met `load config: env: required environment variable "STASH_EMBEDDING_BASE_URL" is not set` (en idem voor `STASH_EMBEDDING_API_KEY`), terwijl er wél een URL in `.env` stond. Twee oorzaken die elkaar versterkten: (1) `config.NewFromFile` parseert met `env.Options{RequiredIfNoDef: true}`, wat elk veld zónder `envDefault` verplicht maakt — de twee embedding-overrides hebben geen default, terwijl `bootstrap.go` ze juist als optioneel behandelt (leeg = terugvallen op de OpenAI-instellingen). (2) `docker-compose.yml` gaf die twee vars niet door aan de container, dus zelfs een correcte `.env` bereikte Stash via compose nooit.
- Conclusions: De overrides echt optioneel gemaakt met `envDefault:""` — dat is precies wat `RequiredIfNoDef` als "heeft een default" ziet, dus ze zijn niet meer verplicht — in plaats van `RequiredIfNoDef` weg te halen, zodat het vangnet voor toekomstige velden blijft staan. Compose geeft ze nu door met `${VAR:-}`, zodat een override uit `.env` de container bereikt en leeg blijft als je 'm niet zet. Regressietest toegevoegd zodat dit niet stil terugkomt.
- Actions: `internal/config/config.go` (`envDefault:""` op `EmbeddingBaseURL`/`EmbeddingAPIKey` + comment); `docker-compose.yml` (beide vars doorgeven); nieuw `internal/config/config_test.go` (2 tests: leeg = geen fout en leeg, gezet = gelezen); validated — `go test ./internal/config/...` groen, `go build ./...` groen.

## 2026-10-13 (Vijf consolidatie-/recall-bugs gefixt)

- Findings: Codebase-review leverde vijf bugs op. (1) Stage 3.5 (causal links) deelde `cp.LastFactID` met de relationships-stage; die schoof het checkpoint al op, dus causal zag vrijwel nooit nieuwe facts (en bij een fout in stage 2 liep het elke run opnieuw over dezelfde facts). (2) `recall_facts` filterde niet op `valid_until`, waardoor door decay/contradictie verlopen facts in recall bleven verschijnen. (3) Bij een dedup-hit werd de bestaande fact niet bijgewerkt, terwijl decay op `updated_at` draait: vaak herbevestigde kennis verviel toch. (4) Eén falend cluster blokkeerde het hele episode-checkpoint (hele batch opnieuw = extra LLM-calls/kosten); `processed` was dode code; bij ctx-cancel kon het checkpoint juist voorbij onverwerkte clusters springen. (5) `||` in de pattern-bronnen vulde bij een ontbrekende rel-lijst álle facts én relaties in.
- Conclusions: (1) eigen checkpoint `last_causal_fact_id`, zoals goal/failure/hypothesis al hebben. (2) filter `valid_until IS NULL OR > now()` in recall. (3) dedup reinforcet nu: `updated_at = now()`, confidence +20% van de resterende ruimte, extra `fact_sources`; de dedup-lookup negeert nu verlopen/vervangen facts (`valid_until IS NULL`, consistent met de contradictie-code) zodat een opnieuw geobserveerde waarde niet door een verlopen fact wordt opgeslokt; een DB-fout daar wordt nu gemeld i.p.v. stil als "geen duplicaat" behandeld. (4) checkpoint schuift alleen over een aaneengesloten reeks voltooide episodes (`contiguousCheckpoint`), en alleen als het ophalen schoon was. (5) `&&`: alleen terugvallen op "alle bronnen" als beide lijsten leeg zijn.
- Actions: nieuwe migratie `00021_add_causal_checkpoint.sql`; `internal/models/models.go` (`LastCausalFactID`); `internal/brain/namespace.go` (scan/save kolom); `internal/brain/consolidate.go` (causal-checkpoint, `reinforceFact`, `factExistsByVector` geeft id+error terug, `contiguousCheckpoint`, `&&`-fix, dode `processed` weg); `internal/queries/recall.sql.tmpl` (valid_until-filter); nieuw `internal/brain/consolidate_test.go`; validated — `gofmt -l .` leeg, `go build`, `go vet`, `go test ./...` groen. ## 2026-10-13 (Relationship-extractie batchen: 1 LLM-call per 5 facts)

- Findings: Stage 2 (facts → relationships) deed één LLM-call per fact (tot 50 per run), de grootste vaste kostenpost na de output-token-fix. Alleen deze stage is een echte N+1: stage 1 clustert al (1 call per cluster), causal/goal/failure/hypothesis/patterns zijn al batch-calls, en contradictie-classificatie is per feitenpaar en begrensd.
- Conclusions: `ReasonRelationships(fact)` vervangen door `ReasonRelationshipsBatch(facts)`: facts gaan genummerd (`[id] tekst`) in één prompt en elke relatie komt terug met een `fact_id`. De grounding-eis blijft per fact bestaan (entiteiten moeten letterlijk in de tekst van dát fact staan), maar ongegronde items worden nu individueel genegeerd i.p.v. de hele call te herhalen. Default batchgrootte 5 (`STASH_RELATIONSHIP_BATCH_SIZE`), bewust laag: de reply moet binnen `STASH_REASONER_MAX_TOKENS` (1024) passen, anders wordt de JSON afgekapt en faalt de batch. Checkpoint gebruikt dezelfde `contiguousCheckpoint` als stage 1 (nu op ID's), dus een falende batch blokkeert de eerdere niet en wordt de volgende run opnieuw geprobeerd. Verwachte besparing: ~5× minder calls in stage 2 (50 → 10 per run); prompt-tokens per call stijgen licht, output-tokens per fact blijven gelijk.
- Actions: `internal/reasoner/reasoner.go` (interface), `internal/reasoner/openai.go` (`ReasonRelationshipsBatch`, `groundRelationships`, `fact_id` in `jsonRelationship`), `internal/brain/consolidate.go` (stage 2 in batches, `contiguousCheckpoint` op ID's), `internal/brain/brain.go` + `internal/config/config.go` + `internal/bootstrap/bootstrap.go` (`RelationshipBatchSize`), `docker-compose.yml` en `.env.example`; tests `internal/reasoner/openai_test.go`, `consolidate_test.go` aangepast. Validated — gofmt, go build, go vet, go test groen. Niet tegen een echte LLM getest: de promptkwaliteit bij batches is onbewezen.

Een vraag als "welke poort draait stash?" vond daardoor soms niet het fact met de letterlijke term.
- Conclusions: Postgres full-text naast de bestaande vector-search, samengevoegd met reciprocal rank fusion (k=60): robuust zonder score-kalibratie tussen twee heel verschillende rankers (cosine vs ts_rank_cd). Geen extra dependency of extern systeem nodig. Configuratie `simple` (geen stemming/stopwoorden) omdat de inhoud NL én EN is en stemming dan voor één van beide fout zou zijn. De zoekterm wordt in Go omgezet naar een OR-query (`a or b or c`, na het strippen van leestekens, dubbele termen, losse letters en NL/EN-stopwoorden), want een natuurlijke vraag als AND-query vindt bijna niets, en de ontdane tekens maken de input veilig voor `websearch_to_tsquery`. Fact-voor-episode-prioriteit blijft: facts eerst, episodes vullen de resterende plekken. `Score` is bij hybrid de RRF-score genormaliseerd naar 0..1 (1 = bovenaan in beide lijsten); de ruwe cosine blijft beschikbaar in het nieuwe veld `similarity`, en `match` (`vector`/`keyword`/`hybrid`) toont hoe een resultaat gevonden is. De schaal is bewust ook zonder keyword-hits de RRF-schaal, zodat scores niet per query van betekenis wisselen. Uitschakelen kan met `STASH_HYBRID_RECALL=false` (dan exact het oude gedrag, inclusief cosine-score). Bekende beperking: hostnamen/URL's worden door de `simple`-parser als één token gezien, dus zoeken op alleen "8445" vindt `host:8445` niet.

## 2026-10-13 (Reinforcement bij recall: gebruikte facts vervallen niet)

- Findings: Decay draait op `updated_at`, maar alleen consolidatie raakt dat aan. Een fact dat dagelijks via recall wordt gebruikt maar niet opnieuw geobserveerd wordt, verloor na elk venster (7 dagen) 5% confidence en verviel uiteindelijk — terwijl het aantoonbaar nuttig is.
- Conclusions: Recall registreert nu welke facts zijn teruggegeven (`last_recalled_at`, `recall_count`), en decay rekent een fact als "recent gezien" wanneer `GREATEST(updated_at, last_recalled_at)` binnen het venster valt. Confidence blijft bewust ongemoeid: gevraagd worden is geen nieuw bewijs, het stelt alleen het verval uit. Alleen facts worden bijgehouden (episodes vervallen niet). De update is best-effort en kan een recall nooit laten falen. Bijeffect: ook zoekopdrachten via het dashboard/CLI tellen mee; voor een geheugen van één gebruiker is dat acceptabel.
- Actions: nieuwe migratie `00023_add_recall_tracking.sql`; `internal/brain/recall.go` (`touchRecalledFacts`); `internal/brain/decay.go` (decay-voorwaarde + doc). Validated — gofmt, go build, go vet, go test groen; SQL niet tegen een echte Postgres gedraaid.
